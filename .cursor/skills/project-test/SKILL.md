# Project Test (SOP stage)

Loaded only by `sop-orchestrator`. Prefer Chinese unless the user writes otherwise.

**Announce:** 「正在使用 `project-test`：用例目录 → 代码测试 + 浏览器产品测试 → 脚本回归。」

For a historical project, read
`project://intake/handoffs/TEST.md` before
building the catalog. Preserve usable existing suites/commands, map them to
F/AC/API/P traces, then add—not replace—the missing coverage.

## When

| Trigger | Do |
|---------|----|
| User confirmed `ARCH_SIGNOFF` | **Create/refresh TEST_PACK** |
| ARCH `CODING_HANDOFF.md` published but `ARCH_SIGNOFF` not confirmed | Return to orchestrator; do not package tests or start CODE |
| User asks 封装测试 / 补用例 | Expand catalog toward full coverage |
| Any runtime-affecting CODE change, or user 回归 | **Run full regression via scripts** |

## Artifact root

`project://test`

Code-test **files** live in the CODE repo (so they run with the app). This pack stores catalog, mappings, product specs, and wrappers.

```text
test/
  README.md
  catalog.yaml
  coverage.md
  code/mapping.yaml          # case_id → pytest/jest/maven node
  product/                   # Playwright against access_url
    package.json
    playwright.config.ts
    tests/*.spec.ts
  scripts/
    run-code.ps1
    run-product.ps1
    run-all.ps1
  runtime.ps1
  last-run.json              # generated by the runner; not copied as a placeholder
```

On first pack: copy `projects/_template/test/` then fill `runtime.ps1` and expand `catalog.yaml`. Product dir uses the committed lockfile and `npm ci` (`@playwright/test` is exact-pinned).

Templates: [templates/catalog.yaml](templates/catalog.yaml), [templates/coverage.md](templates/coverage.md).

Repo wrappers: `scripts/run-full-regression.ps1`.

## 1. Build catalog (full coverage, not smoke-only)

Read, in order:

1. REQ `PRD.md` — every `AC-xx`, in-scope `F-xx`, key `P-xx` states
2. ARCH `05-api-data.md` + `06-nfr-ops.md` — resources, errors, authz, SLO checks that are testable
3. UI `design-spec.md` + prototype routes — happy path + empty/loading/error
4. `sample-data/` if present — fixtures, not extra product rules

Every **in-scope** AC-xx and every documented API resource must appear in `catalog.yaml` with:

- `id` (stable, e.g. `AC-03`, `API-users-list`, `P-01-empty`)
- `layer`: `code` | `product` | `both`
- `priority`: P0/P1/P2
- `trace`: F-xx / AC-xx / P-xx / API
- `script`: mapping key or Playwright file

`both` is the default for user-visible features: unit/integration **and** a browser path.

Do not drop cases because they are “obvious”. Mark `deferred` only with a reason (out of scope in PRD, or no UI yet).

## 2. Code tests

- Prefer TDD files under the CODE repo (`tests/`, `*.spec.ts`, `src/test/`).
- Record node ids in `code/mapping.yaml`.
- Wrapper discovers the real command from CODE README/CI (`pytest`, `npm test`, `./mvnw test`) — never assume one tool.
- If CODE does not exist yet, write **skeletons** (describe + skip or `it.todo`) and still list them in the catalog.

`dev-agent` verify and SOP `project-test` have different boundaries:

- **dev-agent verify** is slice-local developer feedback while implementing: focused unit/integration checks, typecheck/build, and a smoke check needed to prove the edited slice.
- **project-test** owns the cross-slice TEST_PACK, browser product paths, artifact validation, freshness enforcement, and the full regression record in `last-run.json`.
- A green dev-agent verify never substitutes for the post-change project-test regression.

## 3. Product tests (browser)

- Playwright against CODE `access_url` (from handoff / Run Card).
- One spec per P-xx or critical flow; cover listed states.
- Use `sample-data` accounts when present.
- Config lives in `test/product/`. `run-product.ps1` fails fast if `access_url` missing.

## 4. Run regression (save tokens)

1. Prefer CLI: `projects/<slug>/test/scripts/run-all.ps1` or repo `scripts/run-full-regression.ps1 -Slug <slug>` (`mode=full`).
2. Script writes `last-run.json` (`mode`, suite counts, `overall`), then runs the schema/artifact validator before updating machine regression state. A validator failure fails the run and cannot stamp `passed`. Only `mode=full` with both suites executed and passed updates `regression.state=passed` and `last_regression_at`. Partial wrappers never stamp a full REGRESSION pass. Non-skipped suites with zero executed tests fail.
3. Agent **reads last-run.json** and only investigates `failed` / `timed_out`.
4. Use MCP **`playwright`** only to debug a failing spec or author a new one — not to re-run the whole catalog in chat.
5. Optional smoke of `access_url` with **`cursor-ide-browser`** when scripts cannot start (report as unofficial).

Validate machine artifacts without interpreting Markdown gates:

```powershell
python .cursor/skills/project-test/scripts/validate-test-artifacts.py `
  projects/<slug>/test/catalog.yaml `
  --slug <slug> `
  --test-root projects/<slug>/test `
  --last-run projects/<slug>/test/last-run.json `
  --require-trace AC-01
```

The validator checks JSON schemas, unique IDs, unconfigured/placeholder sentinels,
catalog.slug vs project slug, required traces, and that non-deferred `code` /
`product` / `script` paths exist. `run-full-regression.ps1` runs this preflight
before deciding `overall`. It does not inspect Markdown checkboxes and never
approves `TEST_PACK_READY` or `REGRESSION_PASS`.

On first pack: copy `projects/_template/test/` then replace every `unconfigured`
sentinel in `catalog.yaml`. Empty cases or leftover `{{placeholders}}` fail preflight.

Do not paste the catalog into chat. Do not re-generate cases unless coverage is stale vs PRD/ARCH.

Fail routing: [impact.md](../sop-orchestrator/impact.md) fail class table.

## Stale pack

Refresh catalog when PRD AC/F/P or ARCH `05`/`06` changed. Set SOP.md `test_pack_at` to now.

## Hard rules

- Tests do not redefine product rules. Conflicts → REQ/ARCH, not “fix the assertion to match code”.
- CODE READY does not skip product tests after a runtime change.
- Never mark REGRESSION pass if `last-run.json` is older than `last_code_change_at`.
- A missing or invalid `last_code_change_at` is a machine-state error, not
  permission to bypass freshness. After a runtime-affecting change, CODE must
  return to SOP and run `scripts/touch-code-change.ps1 -Slug <slug>
  -DecisionMaker <chat-identity> -ConfirmationQuote <user-request>
  -Reason <runtime-change>`. This single entry point invalidates
  `CODE_READY`/`REGRESSION_PASS`/`DOCS_COMPLETE` before stamping the change.
- `last-run.json` `mode` must be `full` and `overall` must be `PASS` before presenting `REGRESSION_PASS` evidence. Machine state never approves the gate.
- Markdown checkboxes remain human gates checked in chat; regression scripts validate only timestamps and machine artifacts.

## Historical supplement closeout

When applying an intake SUP item to a canonical artifact:

1. Edit the canonical file at this stage's sibling root (never the SOP intake copy).
2. Add a `BACKFILL-<STAGE>-<nnn>` row to `project://intake/evidence-map.md` citing intake evidence and the canonical path.
3. Run:

```powershell
.\scripts\apply-supplement.ps1 -Slug <slug> -SupplementId SUP-... `
  -CanonicalTarget <absolute-or-relative-path> -BackfillId BACKFILL-... `
  -AppliedBy "<identity from chat>" -TargetStage <STAGE>
```

4. Keep the `validate-supplement.ps1` report as provenance evidence.
5. Do not treat applied/waived as a human gate. Stage sign-off remains conversational.
