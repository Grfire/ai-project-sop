# 方向（Direction）

在写任何 UI 代码前读完并执行。

## 1. 接地题材

若 brief 未钉死，先自行钉死并记下：

- 具体题材（产品/主题是什么）
- 受众
- 页面的**单一工作**

从题材的材料、工具、器物、行业语汇里长出视觉选择，而不是从「通用 SaaS 模板」长出。

## 1.5 风格筛选必须看见（接 visual-choice-first）

- **开场：** 先做 **6 版**可点选风格 mockup，再收窄 token；不要用「偏红 / 偏蓝」文字选项代替
- **拍板：** 布局气质、设计节确认等同理——出画面再问「选哪 / 像不像」
- 选定前不要把某一版 token 写进实现代码

## 2. 设计计划（两趟）

**第一趟 — 产出紧凑 token 系统（在用户筛完风格之后）：**

- **Color：** 4–6 个具名色 + hex
- **Type：** 至少显示 + 正文两个角色（可加数据/说明用的第三角色）；具名字体，避免 Inter / Roboto / Arial / 系统默认栈作显示字
- **Layout：** 一句话布局概念 + 必要时 ASCII 线框
- **Signature：** 本页只记住的一个签名元素（且服务题材）

**第二趟 — 自检：**  
若换成「任意同类页面」提示词也会得到几乎相同的计划 → 改掉撞车部分，再写代码。

## 3. 禁止的默认脸（除非 brief 明文要求）

1. 暖奶油底（约 `#F4F1EA`）+ 高对比衬线显示字 + 陶土色强调
2. 近黑底 + 单一酸绿/朱红强调 + 发光
3. 大报/hairline 零圆角密栏排版
4. 紫→靛渐变、紫白主题、圆角胶囊堆、多层阴影、emoji 当图标

## 4. 克制

- 大胆用在**一处**（签名元素）；其余安静
- 结构装置（编号、眉题、分隔）必须编码真实信息，不为装饰而编号
- 离开前「摘掉一件配饰」

## 5. 文案即设计

- 用用户能控制/认识的词，不用系统实现词
- 按钮：动词在前、说清结果（「保存更改」不是「提交」）
- 错误：说明发生了什么与如何修复；不空泛道歉
- 空态：一个明确下一步
- 默认主动语态；全流程同一动作同一名称

## 6. 与 craft 的分工

- 本文件决定气质、调性、记忆点
- `craft.md` 决定间距节奏、动效性能、焦点与状态是否合格
- 不要在本文件规定具体 CSS 框架 API
