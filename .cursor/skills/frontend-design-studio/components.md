# 组件模式（精选）

栈无关。使用项目已有的无障碍原语（任意框架的 focus 管理组件），不要手写残缺的焦点陷阱。

需要百科级 60+ 组件时见 `usage-map.md`（可选 ui-design-brain）。

### Button
- **何时用：** 触发动作
- **关键规则：** 动词在前；同一区域仅一个主按钮；主/次/第三级视觉权重分明
- **状态与无障碍：** hover/focus/active/disabled；图标按钮要 accessible name；危险操作用确认
- **反模式：** 主次按钮视觉权重相同；disabled 提交却不说明缺什么

### Text input / Textarea / Field
- **何时用：** 收集短/长文本
- **关键规则：** 可见 label（勿只用 placeholder 当标签）；placeholder 仅作格式提示；相关字段成组
- **状态与无障碍：** 校验宜在 blur 或提交时，勿每个按键打断；错误文案贴在字段旁；`autocomplete` 合理时开启
- **反模式：** 无 label；错误只在顶部且找不到对应字段

### Select / Combobox
- **何时用：** 从已知选项中选一（或可搜索的较长列表用 Combobox）
- **关键规则：** 选项 ≤7 可考虑直接露出；很长列表必须可搜索；默认值要有意义或明确「请选择」
- **状态与无障碍：** 键盘可打开/移动/选中；选中项朗读名称；禁用选项不可聚焦选中
- **反模式：** 用原生 select 塞几百项却不可搜索；用下拉伪装导航

### Checkbox / Radio / Toggle
- **何时用：** Checkbox=多选；Radio=互斥单选；Toggle=立即生效的开关
- **关键规则：** Toggle 只用于立即生效；需「保存」的表单用 Checkbox；Radio 至少两项
- **状态与无障碍：** 点击 label 可切换；组要用 fieldset/legend 或等价；状态变化可感知
- **反模式：** 用 Toggle 却还要点保存；单选项却用 Checkbox

### Table
- **何时用：** 结构化、可比较的行列数据
- **关键规则：** 表头固定（长表）；数字右对齐；提供排序时状态可见；空表用 Empty state
- **状态与无障碍：** 表头与单元格语义关联；排序按钮可键盘操作；行操作勿只靠悬停才出现（触控要可达）
- **反模式：** 用卡片栅格硬凑本该是表的数据；表头与内容列对不齐

### Tabs
- **何时用：** 同级面板切换（2–7 个）
- **关键规则：** 仅一个面板可见；激活态明确；移动端过挤时可改为手风琴
- **状态与无障碍：** 方向键切换；`aria-selected` / 等价；面板与 tab 关联
- **反模式：** 用 Tabs 做向导步骤（应用 Stepper）；Tab 过多导致不可扫读

### Modal
- **何时用：** 需要打断并聚焦完成的短任务
- **关键规则：** 提供关闭（X / 取消 / Escape）；短内容；复杂流改用页面或 Drawer
- **状态与无障碍：** 打开时焦点陷阱；关闭后焦点回到触发器；背景不可交互
- **反模式：** Modal 套 Modal；无关闭路径；长表单塞进 Modal

### Drawer
- **何时用：** 二级详情或辅助导航，保持上下文
- **关键规则：** 右开常用于详情；左开常用于导航；宽度克制（桌面约一栏，勿全屏吞没除非必要）
- **状态与无障碍：** 同 Modal 的焦点与 Esc；滚动锁定在抽屉内
- **反模式：** 与 Modal 无差别地滥用；无标题导致不知上下文

### Toast
- **何时用：** 短暂确认（成功/次要提示）
- **关键规则：** 自动消失约 4–6s；可手动关闭；破坏性操作最好带撤销
- **状态与无障碍：** 勿抢焦点；用 aria-live 礼貌通知；多条堆叠最新在上或按平台惯例
- **反模式：** 用 Toast 报必须阅读的错误（应用 inline / Alert）；连珠炮 Toast

### Alert
- **何时用：** 页面内需要持续可见的重要状态
- **关键规则：** 语义色 + 图标；最多两句；说明如何处理
- **状态与无障碍：** 角色与语气匹配（info/warning/error）；可关闭时保留关闭按钮
- **反模式：** 彩虹状态条无语义；把营销横幅伪装成 Alert

### Navigation / Header
- **何时用：** 站内/应用内分区跳转
- **关键规则：** 桌面 5–7 项为佳；当前项明确；品牌/产品名可点回首页或主区
- **状态与无障碍：** 跳过链接到主内容；移动端展开菜单可键盘关闭；当前页 `aria-current`
- **反模式：** 桌面无必要隐藏成汉堡；导航项文案含糊

### Empty state
- **何时用：** 无数据或未开始
- **关键规则：** 简短说明 + 一个明确主行动；语气正面务实
- **状态与无障碍：** 主行动可聚焦；装饰图有意义则保留 alt，纯装饰则空 alt
- **反模式：** 只有「暂无数据」无下一步；用错误样式表达空态

### Skeleton
- **何时用：** 布局可预期的加载占位
- **关键规则：** 形状贴近真实内容；延迟约 300ms 再出现以免闪烁
- **状态与无障碍：** 用 aria-busy / 礼貌 live；加载完成后移除并聚焦合理处
- **反模式：** 已知结构却只用中心转圈；骨架与最终布局严重不符

### Stepper
- **何时用：** 多步向导，顺序有意义
- **关键规则：** 显示当前步与总步；允许返回已填步骤（除非业务禁止）；提交在最后一步
- **状态与无障碍：** 步骤名可读；完成/当前/未到状态可区分
- **反模式：** 用 Tabs 冒充当向导；隐藏步数让人迷路

### Card（仅交互容器）
- **何时用：** 卡片本身承载选择/导航/操作，去掉容器会损害理解
- **关键规则：** 层级：媒体 → 标题 → 元信息 → 行动；边框与阴影二选一；整卡可点时勿嵌套冲突链接
- **状态与无障碍：** 可点击卡片有明确角色与键盘激活；勿让整卡与内部按钮抢事件且无说明
- **反模式：** 装饰性卡片套卡片；首屏品牌区滥用卡片墙

### Dropdown menu
- **何时用：** 操作或次要导航的短列表
- **关键规则：** 约 7±2 项；危险项置底并用危险样式；分组有分隔
- **状态与无障碍：** 方向键移动；Esc 关闭；触发器与菜单关联
- **反模式：** 超长菜单无搜索；把主导航塞进下拉

### Tooltip
- **何时用：** 补充说明，非关键信息
- **关键规则：** 短；不承载必须信息（必须信息应常显）；触控设备慎用纯 hover
- **状态与无障碍：** 不抢焦点；可用键盘触发时需可关闭；内容进可访问名称策略要一致
- **反模式：** 用 Tooltip 藏必填说明；大段教程塞进 Tooltip

### Pagination
- **何时用：** 大数据集分页浏览
- **关键规则：** 显示当前范围与总量（若可知）；上一页/下一页禁用态明确
- **状态与无障碍：** 链接或按钮语义正确；当前页标明
- **反模式：** 无限「加载更多」却无终点提示；页码海无省略

### Search
- **何时用：** 在集合中查找
- **关键规则：** 可提供快捷键（如 Ctrl/Cmd+K）若产品合适；输入防抖约 200–300ms；无结果用 Empty state
- **状态与无障碍：** 有 label 或 aria-label；结果更新可感知；清除按钮可及
- **反模式：** 搜索框无提交/无即时反馈且用户不知是否生效

### File upload
- **何时用：** 用户提供文件
- **关键规则：** 写清类型与大小限制；支持拖放时也要有点击备用；显示队列与进度
- **状态与无障碍：** 错误具体到文件；键盘可激活文件选择；进度可感知
- **反模式：** 失败只说「上传失败」；无大小/类型限制说明

### Badge
- **何时用：** 状态或短元数据标签
- **关键规则：** 1–2 词；状态色有语义且有限；不靠颜色 alone 传达
- **状态与无障碍：** 文本本身可读；图标徽章有名称
- **反模式：** 彩虹徽章无语义；把长句塞进 Badge
